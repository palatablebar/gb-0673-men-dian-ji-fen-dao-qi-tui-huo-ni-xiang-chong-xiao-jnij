# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

# 会员等级

会员净积分=该会员全部批次可用余额（remaining）合计。等级门槛在 context.tiers 配置，按门槛降序匹配，净积分达到最高档门槛即入该档，末档为零门槛兜底。等级周期取 context.level_period，下一周期为 next_period。

等级变化方向感知：候选等级高于当前等级时升级，当期立即生效；候选低于当前等级时降级，当期保留原等级、已确认礼遇不追回，候选等级记入 pending_tier 于 next_period 生效；相同为不变。

发布前置对账闸门（reconcile_net）须三项全过：会员批次净积分与归档余额逐户一致（member_net_matched）、净额合计等于总账可用积分（net_total_matched）、全局行守恒与积分守恒且无退货异常（global_gate_passed）。任一不过，等级禁止发布并返回 RECONCILE_BLOCKED。

tier_versions 表仅追加：每次发布按会员生成单调递增 version，含 tier、pending_tier、net_points、effective_period、来源 run_id/run_sha 与 basis_digest。basis_digest 由来源批次摘要、会员、净积分、候选等级与规则版本派生，加唯一约束；同一依据（含同一退货重试）重复发布只回显已发布版本、不新增版本号。写入在单事务内完成，冲突或闸门失败整体回滚，旧版结果保留，历史版本不更新不删除。
